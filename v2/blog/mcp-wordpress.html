Résumé IA

Le MCP WordPress relie Claude à un site WordPress grâce au plugin officiel MCP Adapter, à un mot de passe d'application et à un connecteur personnalisé. L'extension Enable Abilities for MCP ouvre la lecture et l'écriture des articles, pages et menus. Il faut WordPress 6.9 ou plus, un compte administrateur et un site en ligne en HTTPS.

Synthèse rédigée à partir de l'article.

Rédiger dans Claude, copier, coller dans l'éditeur, refaire les intertitres, remettre les liens, remplir la méta-description : c'est le quotidien de beaucoup de gens qui publient avec l'IA. Le MCP WordPress supprime ce copier-coller. Claude lit vos articles, vos pages et vos menus directement sur le site et, si vous l'y autorisez, il crée et modifie lui-même.

J'ai fait l'installation complète en vidéo, sur le site d'un client, en un peu plus de trois minutes. Cet article reprend chaque étape avec ce qui ne tient pas dans une vidéo courte : l'URL à reconstituer sans erreur, les causes d'échec les plus fréquentes et les réglages de sécurité à ne pas oublier.

À retenir

  • Le MCP WordPress repose sur deux briques gratuites : le plugin officiel MCP Adapter, publié par WordPress, et l'Abilities API, intégrée au cœur depuis WordPress 6.9.
  • Toute la connexion tient dans une URL : https://identifiant:MOT_DE_PASSE_APP@domaine/wp-json/mcp/mcp-adapter-default-server.

  • Ce mot de passe ouvre votre site en administrateur : ne le partagez jamais, et révoquez-le dès qu'il ne sert plus.

Connecter WordPress à Claude : la réponse courte

  1. Vérifiez que le site tourne sous WordPress 6.9 ou plus récent, en HTTPS, et que vous avez un compte administrateur.
  2. Téléchargez mcp-adapter.zip dans la dernière release du dépôt GitHub WordPress/mcp-adapter, puis installez-le : Extensions > Ajouter une extension > Téléverser une extension.
  3. Dans Comptes > Profil, créez un mot de passe d'application nommé « Claude » et copiez-le.
  4. Dans Claude, ouvrez Connecteurs, ajoutez un connecteur personnalisé et collez l'URL du connecteur complétée avec vos trois valeurs.
  5. Installez l'extension Enable Abilities for MCP pour donner à Claude le droit de lire et d'écrire.
  6. Redémarrez Claude, activez le connecteur dans une conversation et demandez-lui s'il voit votre site.

Chaque étape est détaillée plus bas, avec un générateur qui assemble l'URL du connecteur à votre place. Si quelque chose bloque, la section dépannage couvre les huit causes que je rencontre le plus souvent.

Le MCP WordPress, concrètement

MCP, pour Model Context Protocol, est une prise standard entre un modèle d'IA et un logiciel : le logiciel expose ce qu'il sait faire, le modèle s'y branche et appelle ces fonctions lui-même. Si la notion est nouvelle pour vous, j'explique en détail ce qu'est un serveur MCP et à quoi il sert.

Côté WordPress, la prise se monte en deux temps. Depuis la version 6.9, sortie fin 2025, le cœur de WordPress embarque l'Abilities API : un registre où le site et ses extensions déclarent ce qu'ils savent faire (lister les articles, créer une page, ajouter un élément de menu), avec les droits exigés pour chaque action. Le plugin MCP Adapter, maintenu par l'équipe IA de WordPress, traduit ce registre en outils MCP et les publie à une adresse de l'API REST du site : /wp-json/mcp/mcp-adapter-default-server.

Claude ne voit pas des dizaines d'outils d'un coup. Le serveur par défaut lui en donne trois : un pour découvrir les capacités disponibles (mcp-adapter-discover-abilities), un pour lire le mode d'emploi de l'une d'elles (mcp-adapter-get-ability-info), un pour l'exécuter (mcp-adapter-execute-ability). Claude commence donc toujours par faire l'inventaire, puis il agit. C'est exactement ce que vous verrez défiler au premier test.

5 minutes

Ce que l'installation vous donne

Deux extensions, un mot de passe, une URL. Voici ce que ça change au quotidien, et ce que ça demande.

  • Articles, pages et menus lus et modifiés sans quitter Claude
  • Un brouillon rédigé dans la conversation posé dans WordPress en une phrase
  • Tout est gratuit : extensions, API et connecteur
  • Compte administrateur obligatoire
  • Site en ligne uniquement, pas de WordPress local

Temps d'installation : 5 minutes WordPress 6.9+ · MCP Adapter · Claude, plan gratuit ou payant

Ce qu'il faut avant de commencer

  • WordPress 6.9 ou plus récent. L'Abilities API est dans le cœur depuis cette version et l'adaptateur ne fonctionne pas sans elle. Vérifiez dans Tableau de bord > Mises à jour.
  • Un compte administrateur. Avec un compte éditeur, auteur ou contributeur, la connexion ne fonctionne pas. C'est le premier point de blocage.
  • Un site en ligne, en HTTPS. Pour deux raisons. WordPress désactive les mots de passe d'application sur un site sans HTTPS. Et le connecteur personnalisé de Claude se connecte depuis les serveurs d'Anthropic : un WordPress installé sur votre ordinateur, derrière un VPN ou derrière un pare-feu qui filtre les adresses IP reste injoignable.
  • Un compte Claude. Le plan gratuit est limité à un connecteur personnalisé, ce qui suffit pour un site. Je détaille ce que permet la version gratuite dans Claude AI gratuit. Le web, l'application de bureau et Cowork acceptent tous les connecteurs personnalisés.

Les trois liens dont vous aurez besoin

Le plugin : les releases de WordPress/mcp-adapter sur GitHub. L'extension d'écriture : Enable Abilities for MCP sur le répertoire WordPress. Et la documentation d'Anthropic sur les connecteurs personnalisés. Le modèle d'URL est aussi dans la description de la vidéo.

Étape 1 : installer le plugin MCP Adapter

Le plugin se télécharge sur GitHub, dans le dépôt officiel de WordPress.

  1. Ouvrez github.com/WordPress/mcp-adapter et cliquez sur Releases, dans la colonne de droite.
  2. Ouvrez la dernière version (v0.7.0 au moment où j'écris), descendez jusqu'à Assets et téléchargez mcp-adapter.zip. Pas les archives « Source code » : c'est le fichier nommé mcp-adapter.zip qui contient l'extension prête à installer.
  3. Dans WordPress : Extensions > Ajouter une extension > Téléverser une extension, choisissez le fichier, Installer maintenant, puis Activer.

Si vous avez accès au serveur en ligne de commande, WP-CLI fait la même chose en une ligne :

wp plugin install https://github.com/WordPress/mcp-adapter/releases/latest/download/mcp-adapter.zip --activate

Rien à régler ensuite : une fois activé, le plugin crée tout seul le serveur MCP par défaut, celui que Claude va appeler.

Étape 2 : créer un mot de passe d'application

C'est l'étape où il faut être attentif. Les mots de passe d'application existent dans WordPress depuis la version 5.6 et servent exactement à ça : donner à un outil externe l'accès à l'API du site sans lui confier votre vrai mot de passe, et pouvoir le lui retirer à tout moment sans rien changer d'autre.

  1. Allez dans Comptes > Profil (ou survolez votre nom en haut à droite, puis Modifier le profil).
  2. Descendez tout en bas de la page, jusqu'au bloc Mots de passe d'application.
  3. Donnez-lui un nom qui dit à quoi il sert, « Claude » par exemple, puis cliquez sur Ajouter un mot de passe d'application.
  4. Copiez le code affiché et gardez-le de côté le temps de l'installation.

Il ne s'affiche qu'une seule fois

WordPress montre ce mot de passe une fois, puis plus jamais. Si vous le perdez, aucun problème : révoquez-le et créez-en un autre. Ne le rangez pas dans un document partagé : il donne les mêmes droits que votre compte administrateur.

Le code se présente en six blocs de quatre caractères séparés par des espaces, du type abcd EFGH 1234 ijkl MNOP 5678. Les espaces ne servent qu'à la lisibilité : il faudra les retirer dans l'URL.

Pendant que vous êtes sur cette page, remontez tout en haut et notez votre identifiant : c'est le champ grisé, impossible à modifier. Ce n'est pas forcément votre adresse e-mail, ni le nom affiché publiquement sur le site.

Le bloc « Mots de passe d'application » n'apparaît pas ? Le site n'est pas en HTTPS, ou une extension de sécurité a désactivé la fonction. Les solutions sont dans le dépannage.

Étape 3 : ajouter le connecteur personnalisé dans Claude

  1. Dans Claude, ouvrez les Paramètres, puis Connecteurs. Selon votre version, le menu s'appelle aussi Personnaliser > Connecteurs.
  2. Cliquez sur + ou Ajouter, puis sur Ajouter un connecteur personnalisé.
  3. Donnez-lui un nom explicite. Dans la vidéo, j'ai mis le nom du site suivi de « MCP » : pratique dès que vous branchez plusieurs sites.
  4. Dans le champ URL, collez le modèle ci-dessous, remplacez les trois parties (détail juste après), puis cliquez sur Continuer.
  5. À l'écran d'authentification, ne choisissez aucune connexion (« No sign in ») : l'identification est déjà dans l'URL. Cliquez sur Ajouter.
  6. Le connecteur passe en cours de connexion, puis s'affiche comme connecté. Sur l'application de bureau, quittez Claude complètement et rouvrez-le.

L'URL du connecteur, morceau par morceau

Voici le modèle à coller dans le champ URL :

https://identifiant:MOT_DE_PASSE_APP@domaine/wp-json/mcp/mcp-adapter-default-server

Elle a l'air technique, c'est juste un chemin. Ce qui précède le @ dit à WordPress qui se connecte, ce qui suit dit où se trouve le serveur MCP.

PartieCe qu'il faut mettreL'erreur classique
identifiantVotre identifiant WordPress, le champ grisé en haut du profilMettre l'adresse e-mail ou le nom public
MOT_DE_PASSE_APPLe mot de passe d'application de l'étape 2, sans les espacesLaisser les espaces, ou effacer les deux-points qui le précèdent
domaineLe nom de domaine seul : monsite.fr ou www.monsite.frLaisser https:// ou une barre oblique à la fin

Avec l'identifiant marie, le mot de passe abcd EFGH 1234 ijkl MNOP 5678 et le site https://www.monsite.fr/, ça donne :

https://marie:abcdEFGH1234ijklMNOP5678@www.monsite.fr/wp-json/mcp/mcp-adapter-default-server

Deux cas particuliers. Si WordPress est installé dans un sous-dossier (monsite.fr/blog), gardez le sous-dossier avant /wp-json. Et si votre identifiant contient un espace ou un @, ces caractères doivent être encodés (%20 et %40), sinon l'URL est mal lue. Le générateur ci-dessous s'en charge.

    Étape 4 : donner à Claude le droit d'écrire

    À ce stade, Claude voit le site, mais il ne peut presque rien y faire. WordPress garde ses capacités privées par défaut : seules celles qu'une extension déclare publiques passent par le serveur MCP, et le cœur n'en déclare quasiment aucune. L'extension Enable Abilities for MCP comble ce vide.

    1. Extensions > Ajouter une extension, cherchez Enable Abilities for MCP.
    2. Installez la première, celle de Fabio Montenegro, puis activez-la.
    3. Ouvrez Réglages > WP Abilities pour voir et choisir ce que Claude a le droit de faire.

    L'extension déclare plus d'une centaine de capacités, rangées par familles : lecture, écriture, menus, utilitaires, et des modules pour les extensions courantes (Yoast, Rank Math, SEOPress, WooCommerce, Elementor, entre autres). Chacune se coche ou se décoche. Elle respecte aussi les droits WordPress : une capacité d'écriture vérifie que le compte connecté a bien le droit de publier ou de modifier le contenu visé.

    Mon réglage de départ

    Je laisse la lecture, la création et la modification d'articles, et les métadonnées SEO. Je décoche les suppressions, la gestion des extensions et le rechercher-remplacer global, et je demande toujours à Claude de créer en brouillon. J'ouvre le reste quand un vrai besoin se présente, pas avant.

    L'extension activée et réglée, quittez puis relancez Claude pour qu'il recharge la liste des outils.

    Le test : Claude voit-il votre site ?

    Ouvrez une nouvelle conversation. Vérifiez d'abord que le connecteur est actif : bouton + en bas à gauche de la zone de saisie, puis Connecteurs, et l'interrupteur de votre site doit être allumé. Puis demandez simplement :

    Dis-moi si tu as accès au site WordPress [nom du site] via le MCP, et liste ce que tu peux y faire.

    Claude charge le connecteur, appelle l'outil de découverte et vous rend l'inventaire : lecture, écriture, pages, menus, extensions. Selon votre configuration, il peut vous demander de terminer la connexion ou d'autoriser l'outil : validez. Si la liste revient vide, c'est presque toujours l'étape 4 ou le redémarrage oublié.

    Autoriser une fois ou toujours ?

    Claude demande la permission avant d'utiliser un outil. « Toujours autoriser » est confortable pour la lecture. Pour tout ce qui écrit sur le site, je garde la validation à chaque appel : c'est elle qui montre exactement ce que Claude s'apprête à modifier.

    Ce que Claude sait faire une fois branché

    Avec Enable Abilities for MCP, les capacités se rangent en six familles. Ce qui est disponible dépend de ce que vous avez coché et des extensions installées sur le site.

    Cinq demandes qui marchent dès le premier jour

    • L'inventaire : « Liste les 20 derniers articles publiés avec leur titre SEO et leur méta-description, et signale celles qui manquent ou dépassent 155 caractères. »
    • Le brouillon : « Crée un brouillon à partir du texte ci-dessous, dans la catégorie Guides, avec un H2 par partie. Ne publie rien. »
    • Le maillage : « Trouve les articles qui parlent de [sujet] et propose trois liens internes à ajouter dans chacun, sans rien modifier. »
    • Le ménage : « Liste les brouillons qui n'ont pas été modifiés depuis plus de six mois. »
    • Le menu : « Ajoute la page Contact à la fin du menu principal. »

    Le principe est le même que pour n'importe quelle demande à un modèle : ce n'est pas la formule qui compte, c'est le contexte que vous fournissez. Dites quel contenu, quelle action, et ce qui doit rester intact. « Sans rien modifier » et « en brouillon » sont les deux mots les plus utiles de cette liste.

    Le cas du 401 alors que l'URL est juste. Sur beaucoup d'hébergements Apache, l'en-tête qui transporte l'identifiant et le mot de passe est retiré avant d'atteindre WordPress. Depuis la version 5.6, WordPress ajoute lui-même la ligne qui corrige ça dans le .htaccess, mais les sites plus anciens ne l'ont souvent pas. Vérifiez que le bloc WordPress de votre fichier contient bien :

    RewriteEngine On
RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

    Le plus simple pour la faire apparaître : Réglages > Permaliens, puis Enregistrer les modifications sans rien changer. WordPress réécrit alors son bloc. Si vous éditez le fichier à la main, faites-en une copie avant : une erreur de syntaxe met tout le site hors ligne. Sur un serveur Nginx, c'est à l'hébergeur de régler la transmission de l'en-tête.

    Pour savoir si le problème vient de WordPress ou de Claude, un test en ligne de commande tranche en dix secondes :

    curl -u "identifiant:motdepasseapplication" https://www.monsite.fr/wp-json/wp/v2/users/me

    Si la réponse contient votre profil, l'authentification fonctionne et le problème est dans l'URL du connecteur. Si elle renvoie une erreur 401, il est côté site ou hébergement.

    Sécurité : ce que ce mot de passe ouvre vraiment

    Le mot de passe d'application donne à qui le détient les droits de votre compte administrateur sur l'API du site. Et l'URL du connecteur le contient en clair. Traitez-la donc comme un mot de passe : ni dans un message, ni dans un ticket, ni dans une capture d'écran.

    • Un compte dédié. Créez un utilisateur administrateur réservé à Claude, avec son propre mot de passe d'application. Tout ce que Claude fait apparaît sous ce nom dans l'historique des révisions, et couper l'accès revient à supprimer ce compte, sans toucher au vôtre.
    • Révoquer. Dans Comptes > Profil > Mots de passe d'application, chaque mot de passe affiche sa date de dernière utilisation et un bouton Révoquer. Le connecteur ne sert plus ? Révoquez.
    • Le moindre droit. Ne cochez dans WP Abilities que les capacités dont vous avez besoin. Une capacité désactivée ne peut pas être mal utilisée.
    • Les contenus sont des données, pas des ordres. Claude lit ce qui se trouve sur votre site, y compris les commentaires laissés par n'importe qui. Un texte piégé peut tenter de détourner le modèle : c'est le principe de l'injection de prompt. D'où la validation manuelle des outils d'écriture.
    • Une sauvegarde avant. Évident, mais ça mérite d'être écrit : une sauvegarde récente avant la première session d'écriture, et un test sur une copie du site si vous en avez une.

    Pour une équipe, il existe une variante sans mot de passe dans l'URL. D'après sa documentation, Enable Abilities for MCP embarque désormais un serveur OAuth pensé pour les connecteurs de claude.ai : chaque personne se connecte avec son propre compte WordPress et son propre rôle. La méthode de la vidéo reste la plus rapide quand vous gérez le site seul ; dès que plusieurs personnes s'en servent, c'est cette variante que je regarde en premier.

    Et avec Claude Code, ou un WordPress en local ?

    Le connecteur personnalisé passe par les serveurs d'Anthropic, d'où l'obligation d'un site en ligne. Pour un WordPress installé sur votre machine, ou pour travailler depuis Claude Code, le MCP Adapter prévoit deux autres voies, documentées sur le blog développeurs de WordPress.

    Le relais HTTP. Le paquet @automattic/mcp-wordpress-remote tourne avec Node.js sur votre ordinateur et reçoit l'adresse du serveur, l'identifiant et le mot de passe d'application. Dans Claude Code, une commande suffit :

    claude mcp add --transport stdio \
  --env WP_API_URL=https://www.monsite.fr/wp-json/mcp/mcp-adapter-default-server \
  --env WP_API_USERNAME=identifiant \
  --env WP_API_PASSWORD=motdepasseapplication \
  wordpress -- npx -y @automattic/mcp-wordpress-remote@latest

    La même configuration se déclare dans le fichier claude_desktop_config.json de Claude Desktop, avec les trois mêmes variables.

    WP-CLI en direct. Si le site tourne sur votre machine avec WP-CLI installé, Claude peut lancer le serveur lui-même, sans passer par le réseau : la commande est wp mcp-adapter serve --server=mcp-adapter-default-server --user=admin, avec --path vers le dossier du site.

    Ce que ça change dans mon travail

    Je m'en sers surtout pour les tâches de fond qui ne méritent pas une demi-journée : passer en revue les méta-descriptions d'un blog entier, poser les liens internes d'un nouvel article, préparer des brouillons déjà au bon format. Le MCP fait gagner le temps des clics, pas celui de la réflexion : décider quoi publier, pour qui et pourquoi reste votre travail.

    C'est le même branchement que j'ai montré avec le MCP de Screaming Frog pour les crawls, appliqué cette fois au CMS. Et si vous voulez aller plus loin que le connecteur, avec des automatisations qui tiennent en production sur vos propres outils, c'est tout le sujet de l'automatisation IA.

    Questions fréquentes

    Comment connecter WordPress à Claude ?

    Il faut WordPress 6.9 ou plus récent, un compte administrateur et un site en ligne en HTTPS. Installez le plugin MCP Adapter (fichier mcp-adapter.zip de la dernière release GitHub), créez un mot de passe d'application dans votre profil WordPress, puis ajoutez dans Claude un connecteur personnalisé avec l'URL https://identifiant:MOT_DE_PASSE_APP@domaine/wp-json/mcp/mcp-adapter-default-server. Ajoutez l'extension Enable Abilities for MCP pour que Claude puisse lire et modifier le contenu, puis redémarrez Claude.

    Le MCP WordPress est-il gratuit ?

    Oui. Le plugin MCP Adapter et l'extension Enable Abilities for MCP sont gratuits, et l'Abilities API fait partie de WordPress depuis la version 6.9. Côté Claude, le plan gratuit accepte un connecteur personnalisé, ce qui suffit pour brancher un site. Les plans payants lèvent cette limite et offrent davantage d'usage.

    Faut-il être administrateur du site WordPress ?

    Oui. Avec un compte éditeur, auteur ou contributeur, la connexion ne fonctionne pas : le mot de passe d'application doit être créé sur un compte administrateur. Pour garder une trace claire de ce que fait Claude, l'idéal est un compte administrateur qui lui est dédié, que vous pouvez supprimer sans toucher au vôtre.

    Quelle URL mettre dans le connecteur personnalisé de Claude ?

    Le modèle est https://identifiant:MOT_DE_PASSE_APP@domaine/wp-json/mcp/mcp-adapter-default-server. Remplacez identifiant par votre identifiant WordPress (le champ grisé du profil), MOT_DE_PASSE_APP par le mot de passe d'application sans les espaces, en gardant les deux-points qui le précèdent, et domaine par le nom de domaine seul, sans https:// ni barre oblique finale.

    Pourquoi Claude n'arrive-t-il pas à se connecter à mon site WordPress ?

    Dans la plupart des cas, c'est l'URL : espaces laissés dans le mot de passe, https:// conservé dans le domaine ou deux-points effacés. Viennent ensuite le compte non administrateur, le site sans HTTPS, une extension de sécurité qui bloque les mots de passe d'application, un hébergeur qui supprime l'en-tête Authorization, et les sites locaux ou protégés, que les serveurs d'Anthropic ne peuvent pas joindre.

    Claude peut-il modifier mon site WordPress ?

    Oui, avec l'extension Enable Abilities for MCP. Sans elle, Claude est connecté mais n'a presque aucune action disponible. Avec elle, il peut lire, créer et modifier articles, pages, menus, catégories et métadonnées SEO, dans la limite des capacités cochées dans Réglages, WP Abilities, et des droits du compte connecté.

    Est-ce risqué de donner à Claude un accès administrateur ?

    Le risque est réel, et il se maîtrise. Le mot de passe d'application donne les droits du compte : ne le partagez jamais, révoquez-le dans votre profil dès qu'il ne sert plus, n'activez que les capacités utiles et gardez la validation manuelle pour les actions d'écriture. Faites une sauvegarde avant la première session, et méfiez-vous des contenus que Claude lit sur le site, comme les commentaires, qui peuvent contenir des instructions piégées.

    Est-il possible d'utiliser le MCP WordPress avec Claude Code ou un site en local ?

    Oui, mais pas avec le connecteur personnalisé, qui passe par les serveurs d'Anthropic et exige un site accessible en ligne. Pour Claude Code ou Claude Desktop, le relais @automattic/mcp-wordpress-remote se lance avec Node.js et reçoit l'adresse du serveur, l'identifiant et le mot de passe d'application. Pour un site installé sur votre machine, le MCP Adapter fonctionne aussi en direct avec WP-CLI.
