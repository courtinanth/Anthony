Comment fonctionne Claude Code

La différence avec un assistant classique tient en un mot : l'action. Vous décrivez ce que vous voulez, l'agent explore votre projet, propose un plan, puis exécute. Il lit les fichiers dont il a besoin, écrit les modifications, lance les commandes de vérification et corrige ce qui échoue.

Concrètement, une session ressemble à une conversation avec quelqu'un qui a accès à votre machine. Vous dites « les images de la page d'accueil sont trop lourdes, convertis-les et mets à jour les balises », et il le fait. Vous validez chaque étape sensible avant qu'elle ne s'exécute.

Le système de permissions

C'est le point qui rassure les entreprises, et il mérite d'être expliqué. Rien ne s'exécute sans votre accord sur les opérations à risque : modifier un fichier, lancer une commande, accéder au réseau. Vous pouvez accorder une permission ponctuelle, pour toute la session, ou définir des règles permanentes.

En pratique, on commence par tout valider à la main, puis on autorise progressivement les opérations de lecture, qui sont sans danger. C'est le bon réflexe : la prudence coûte quelques clics au début, elle évite des mauvaises surprises ensuite.

Le fichier de contexte projet

Un fichier nommé CLAUDE.md, placé à la racine, est lu automatiquement au démarrage. Il contient ce qu'un nouveau collaborateur aurait besoin de savoir : à quoi sert le projet, quelles technologies, quelles commandes lancer, et surtout quelles règles respecter.

C'est le levier le plus rentable de tout l'outil. Un projet avec un bon fichier de contexte donne des résultats sans commune mesure avec le même projet sans. C'est exactement le principe que je décris dans mon article sur le contexte à fournir avant d'écrire un prompt : ce que vous donnez à lire compte davantage que la façon dont vous demandez.

Installer Claude Code en dix minutes

L'installation se fait en une commande dans un terminal, sur Mac, Windows ou Linux. Vous ouvrez ensuite le dossier de votre projet, vous lancez l'agent, et vous vous authentifiez avec votre compte Claude.

  1. Ouvrez un terminal. Sur Mac, l'application Terminal. Sur Windows, PowerShell ou le sous-système Linux.
  2. Installez l'outil avec la commande donnée sur la documentation officielle.
  3. Placez-vous dans votre dossier de travail et lancez l'agent.
  4. Connectez-vous avec votre compte Claude ou une clé d'API.
  5. Créez votre fichier de contexte avec le générateur ci-dessus.

Il existe aussi des extensions pour les environnements de développement courants, dont Visual Studio Code et les outils JetBrains, ainsi qu'une intégration avec Slack. Elles font la même chose depuis une interface plus familière, ce qui aide beaucoup les personnes que la ligne de commande intimide.

Le terminal fait peur, et c'est le seul vrai obstacle

Je forme régulièrement des profils marketing à cet outil. La difficulté n'est jamais l'agent lui-même, qui parle français et explique ce qu'il fait. C'est l'écran noir. Une fois passée la première demi-heure, la question ne se pose plus. Si cet obstacle vous bloque, commencez par l'extension pour Visual Studio Code.

Ce que je lui confie vraiment

Voici mes usages réels, classés du plus fréquent au moins fréquent. Trois sur cinq n'ont rien à voir avec du développement.

  • Traiter des fichiers en masse. Convertir trois cents images, renommer des exports, croiser deux tableaux de plusieurs milliers de lignes. Ce sont des tâches où l'agent excelle et où le gain est immédiat.
  • Écrire de petits programmes utilitaires. Un script qui vérifie mes redirections, un autre qui surveille les mentions d'une marque. Des outils que je n'aurais jamais pris le temps de développer.
  • Comprendre un projet existant. Arriver sur le site d'un client et demander comment il est construit fait gagner une demi-journée de lecture.
  • Modifier un site. Ajouter une page, corriger un affichage, mettre à jour un gabarit sur toutes les pages d'un coup.
  • Vérifier avant publication. Contrôler des liens, valider des données structurées, repérer les balises manquantes.

Le point commun de ces usages : ce sont des tâches répétitives, mesurables et vérifiables. C'est là que l'agent est le plus fiable, parce qu'il peut contrôler lui-même son résultat.

Les prix et le coût réel

Claude Code est inclus dans les abonnements payants, à partir du plan Pro à 17 dollars par mois en engagement annuel. Il n'y a pas de licence séparée à acheter. Pour un usage soutenu, le plan Max lève les limites d'usage, et l'accès par API permet de payer à la consommation.

Le vrai sujet n'est pas le tarif mensuel mais le quota. Une session longue sur un gros projet consomme beaucoup, parce que l'agent lit énormément de fichiers pour comprendre le contexte. C'est le premier motif de passage au plan supérieur chez mes clients, bien avant le nombre d'utilisateurs. Le détail des offres est dans mon article sur Claude AI et ses abonnements.

Diviser sa consommation par deux

Démarrez une session neuve pour chaque tâche, au lieu d'enchaîner dans la même conversation. Une session longue renvoie tout l'historique à chaque échange. Et soyez précis sur les fichiers concernés : « regarde le dossier des articles » coûte bien moins cher que de laisser l'agent explorer tout le projet.

Trois exemples détaillés, du début à la fin

Les listes d'usages restent abstraites. Voici trois cas réels, avec ce que j'ai demandé et ce qui s'est passé.

Alléger les images d'un site

Demande : « les visuels du dossier images sont trop lourds, convertis-les en AVIF avec un repli WebP, largeur maximale 1400 pixels, et mets à jour les balises dans les pages qui les utilisent ».

L'agent a listé les fichiers concernés, installé la bibliothèque de traitement, écrit le script de conversion, remplacé les balises image par des blocs picture dans une quinzaine de pages, puis affiché le poids avant et après pour chaque visuel. Durée : une dizaine de minutes, contre une bonne demi-journée à la main.

Croiser deux exports

Demande : « voici l'export des pages explorées et celui des pages qui reçoivent des impressions, dis-moi lesquelles sont dans le premier mais pas dans le second ».

C'est le croisement que je décris dans mon article sur la méthode d'audit SEO, et qui révèle en quelques minutes les problèmes d'indexation et de maillage. L'agent a lu les deux fichiers, fait la comparaison, et rendu la liste triée par profondeur de page. Aucun tableur ouvert.

Vérifier un site avant mise en ligne

Demande : « parcours toutes les pages du dossier, vérifie que chaque page a un titre de moins de soixante signes, une description, une balise canonique, et signale les liens internes cassés ».

Il a produit un tableau récapitulatif page par page, avec les anomalies en évidence. C'est devenu un contrôle systématique avant chacune de mes mises en production, et il coûte deux minutes.

Est-ce vraiment efficace

Il faut être honnête sur les limites, parce qu'elles existent et que les retours d'utilisateurs déçus ne sont pas tous de mauvaise foi.

L'agent est excellent sur les tâches bien délimitées et vérifiables. Il est moins bon quand la demande est floue, quand le projet est mal organisé, ou quand la bonne réponse dépend d'un contexte métier qu'il n'a pas. Dans ces cas, il produit quelque chose de plausible mais inadapté, et il faut savoir le repérer.

Ma règle après un an d'usage quotidien : je ne lui confie jamais une tâche dont je serais incapable de vérifier le résultat. Ce n'est pas une question de confiance dans l'outil, c'est une question de responsabilité sur ce que je livre à mes clients.

Par où commencer si vous ne codez pas

  1. Choisissez une tâche répétitive et sans risque. Renommer des fichiers, convertir des images, nettoyer un export. Rien qui touche à de la production.
  2. Travaillez sur une copie. Toujours, les premières semaines.
  3. Décrivez le résultat attendu, pas la méthode. Dites ce que vous voulez obtenir, laissez l'agent choisir comment.
  4. Demandez-lui d'expliquer avant d'agir. La formule « explique-moi ce que tu vas faire avant de le faire » est la meilleure sécurité pour un débutant.
  5. Écrivez votre fichier de contexte dès que vous revenez sur le même projet une deuxième fois.

Comptez une semaine avant que le réflexe s'installe. Le basculement se produit le jour où vous vous surprenez à lui confier une tâche que vous auriez faite à la main sans même y penser un mois plus tôt.

Quelles sont les fonctionnalités de Claude Code ?

Il lit et modifie les fichiers d'un projet entier, exécute des commandes, lance les tests, gère les versions, et se connecte à des outils externes via le protocole MCP. Un système de permissions demande votre accord avant chaque opération sensible. Le fichier CLAUDE.md placé à la racine lui donne le contexte du projet au démarrage.

Claude Code ou GitHub Copilot : quelle différence ?

Copilot complète votre code ligne par ligne pendant que vous écrivez : il vous aide à aller plus vite. Claude Code prend en charge une tâche complète de bout en bout et vous rend compte du résultat. Pour quelqu'un qui ne programme pas, seule la seconde approche est réellement utilisable.

Peut-on utiliser Claude Code sans savoir coder ?

Oui, à condition de savoir décrire précisément un résultat attendu.
