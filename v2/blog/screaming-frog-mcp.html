MCP Screaming Frog : connecter Claude à vos crawls

Screaming Frog sait crawler depuis dix ans. Ce qu'il ne savait pas faire, c'est répondre à une question posée en français. Depuis la version 24, il expose ses crawls à Claude via un serveur MCP : cinq minutes de réglages, et vous demandez vos exports au lieu de les cliquer.

Résumé IA

Le serveur MCP de Screaming Frog laisse Claude lancer un crawl, rouvrir un crawl existant et en sortir les exports et les rapports en langage naturel. L'installation demande une licence payante, le stockage en base de données, l'extension MCP dans Claude Desktop, et un crawl vidé de l'interface pour qu'il devienne visible.

Synthèse rédigée à partir de l'article.

Un crawl Screaming Frog, c'est trente onglets, des dizaines de filtres et autant d'exports à aller chercher. Le travail utile — décider quoi corriger en premier — commence après. Le serveur MCP déplace cette frontière : Claude lance le crawl, ouvre celui d'hier, sort le bon export, et peut même écrire un script Node pour retraiter le fichier avant de vous le rendre.

Je l'ai installé en direct dans la vidéo ci-dessous, sur une machine neuve. Comptez cinq minutes, trois réglages, et un piège qui bloque tout le monde au premier test.

À retenir

  • Le serveur MCP de Screaming Frog est réservé aux licences payantes, en version 24 minimum.
  • Trois réglages suffisent : stockage en base de données, environnement Node.js accepté, extension installée dans Claude Desktop.
  • Deux modes au choix : STDIO, où Claude lance Screaming Frog en tâche de fond, ou Streamable HTTP, où l'interface reste sous vos yeux.
  • Le piège du premier test : tant que le crawl est encore ouvert dans l'interface, Claude ne le trouve pas. Videz-le, il apparaît.
  • Le MCP fait gagner le temps des exports, pas celui de l'analyse : la priorisation reste votre travail.

Ce que le MCP change concrètement

MCP, pour Model Context Protocol, est une prise standard : d'un côté un logiciel expose ce qu'il sait faire, de l'autre un modèle d'IA s'y branche et appelle ces fonctions lui-même. Screaming Frog joue ici le rôle du serveur, Claude celui du client.

Une fois la prise branchée, Claude accède à trois familles d'outils. Les outils de crawl et d'export, d'abord : démarrer un crawl, suivre son avancement, rouvrir un crawl enregistré, sortir un onglet, un filtre ou un rapport complet. Un moteur Node.js, ensuite, qui lui permet d'écrire un script pour retraiter un export trop gros et d'installer les paquets npm dont il a besoin. Un accès fichiers, enfin, limité à un dossier que vous choisissez, pour lire et écrire les résultats.

C'est cette autonomie qui fait la différence avec un simple export manuel : vous décrivez le livrable, Claude enchaîne les étapes techniques pour y arriver.

5 minutes

Ce que l'installation vous donne

Trois réglages à faire une fois, et le crawl devient interrogeable en langage naturel. Voici ce que ça change au quotidien, et ce que ça ne change pas.

  • Les exports et les rapports demandés en une phrase
  • Deux crawls comparés sans ouvrir un tableur
  • Des scripts Node générés à la volée sur vos données
  • Licence Screaming Frog payante obligatoire
  • La fenêtre de contexte se remplit très vite

Temps d'installation : 5 minutes Screaming Frog 24+ · Claude Desktop · macOS ou Windows

Ce qu'il faut avant de commencer

  • Une licence payante de Screaming Frog, en version 24 ou supérieure. La version gratuite n'expose pas le serveur MCP : le réglage n'apparaît même pas.
  • Claude Desktop, l'application de bureau — l'extension ne s'installe pas depuis le navigateur. LM Studio fonctionne aussi, avec un modèle local.
  • Le stockage en base de données activé dans Screaming Frog. C'est le mode par défaut en version 24, mais il vaut mieux vérifier.

Où trouver la procédure officielle

Tout est documenté dans la section « MCP Server » du guide utilisateur de Screaming Frog, avec les deux extensions à télécharger. C'est la page que j'ouvre dans la vidéo.

Étape 1 — Passer en stockage base de données

Direction File > Settings > Storage Mode, et choisissez le stockage en base de données plutôt que la mémoire vive. Redémarrage de l'application à la clé.

Ce réglage n'est pas décoratif. En mode mémoire, un crawl disparaît quand vous fermez l'onglet : il n'existe nulle part sur le disque, donc le MCP n'a rien à rouvrir. En mode base de données, chaque crawl est enregistré, porte un identifiant, et reste consultable des semaines plus tard. C'est ce qui permet de demander « compare les deux derniers crawls du site » sans avoir rien préparé.

Étape 2 — Activer le MCP dans Screaming Frog

Toujours dans les réglages : File > Settings > MCP Server. Deux cases y comptent.

Accepter l'environnement Node.js. C'est lui qui autorise le modèle à exécuter des scripts et à installer des paquets npm à la demande. Sans lui, vous gardez les exports mais vous perdez tout le retraitement — et c'est justement ce qui évite de faire transiter 50 000 lignes par la conversation. Le même écran laisse choisir le dossier où atterrissent scripts, exports et paquets installés : prenez un dossier dédié, pas votre bureau.

Démarrer le serveur MCP. Cette case ne sert qu'en mode Streamable HTTP, décrit plus bas. En mode STDIO, Claude se charge de lancer Screaming Frog tout seul.

Étape 3 — Installer l'extension dans Claude

Depuis le guide utilisateur, téléchargez l'extension correspondant au mode retenu — un fichier .mcpb. Puis, dans Claude Desktop : Settings > Extensions > Advanced Settings > Install Extension, sélectionnez le fichier, validez.

Deux détails qui font perdre un quart d'heure quand on les rate :

  • L'extension suppose que Screaming Frog est installé à l'emplacement par défaut — /Applications sur macOS, C:\Program Files (x86) sur Windows. Ailleurs, il faut éditer le fichier pour corriger le chemin.
  • Il faut quitter Claude complètement, pas seulement fermer la fenêtre. Sur Windows, l'application continue de tourner dans la zone de notification : clic droit sur l'icône, « Quit ». Sinon l'extension ne sera pas chargée au redémarrage.

Rouvrez Claude : dans Settings > Developer, l'extension doit apparaître avec la mention indiquant qu'elle tourne. À partir de là, vous lui parlez normalement.

Étape 4 — Le premier crawl, et le piège du crawl à vider

Le test que je fais dans la vidéo tient en une phrase :

Crawle https://exemple.fr avec Screaming Frog, puis résume-moi les principaux problèmes trouvés, par ordre de priorité.

Claude déclenche le crawl, suit son avancement, puis va chercher le rapport de synthèse des problèmes. Rien à cliquer.

Le piège : videz le crawl une fois terminé

Tant que le crawl reste chargé dans l'interface de Screaming Frog, il n'est pas rangé dans la base de données : Claude ne le voit pas dans la liste des crawls récents et vous répond qu'il n'existe pas. Videz le crawl une fois terminé, redemandez la liste, il apparaît. C'est le seul vrai point de friction de l'installation.

Pour désigner un crawl précis, vous pouvez aussi lui donner son identifiant : clic droit sur le crawl dans File > Crawls. Utile quand plusieurs versions du même site cohabitent.

STDIO ou Streamable HTTP : lequel choisir

Les deux modes donnent accès aux mêmes outils. Ce qui change, c'est qui lance le logiciel et ce que vous voyez pendant l'exécution.

Pour débuter, je conseille Streamable : voir l'onglet s'ouvrir pendant que Claude travaille apprend beaucoup sur ce qu'il fait réellement. Une fois la confiance installée, STDIO est plus confortable — c'est celui de la vidéo.

Ce que Claude sait faire une fois branché

Le serveur expose une trentaine d'outils. Dans la pratique, ils se rangent en cinq familles.

FamilleCe que vous pouvez demander
Piloter un crawlLancer un crawl sur une URL, suivre son avancement, le mettre en pause, le reprendre
Rouvrir l'existantLister les crawls récents, en charger un par son identifiant, comparer deux versions
ExporterUn onglet, un filtre, des champs choisis, les exports groupés, les rapports (chaînes de redirection, problèmes, etc.)
RetraiterÉcrire un script Node.js sur un export, installer les paquets nécessaires, produire un tableau ou une page HTML
Inspecter une URLContenu, liens entrants et sortants, informations techniques, capture d'écran de la page

Cinq demandes qui marchent dès le premier jour

Les prompts qui donnent de bons résultats ont un point commun : ils nomment l'onglet, le filtre et le livrable. Le modèle n'a plus à deviner où chercher.

  • Le point de départ : « Crawle exemple.fr, puis liste les problèmes du rapport de synthèse par priorité en distinguant ce qui est vraiment urgent du reste. »
  • Les liens cassés : « Exporte tous les codes de réponse non-200 avec leurs liens entrants dans un seul fichier CSV. »
  • Le suivi : « Ouvre les deux derniers crawls de exemple.fr, compare les problèmes principaux et résume ce qui a changé. »
  • Le maillage interne : « Exporte les URLs HTML de l'onglet Internal dans un fichier, avec les champs Address et Unique Inlinks, puis sors le top 20 des pages les plus maillées sous forme de graphique HTML. »
  • Les images : « Exporte toutes les images de plus de 100 ko et génère une page HTML qui les affiche en grille, avec leur poids sous chacune. »

Le principe est le même que pour n'importe quelle demande à un modèle : ce n'est pas la formule qui compte, c'est le contexte que vous fournissez. Ici, le contexte, c'est le crawl — encore faut-il dire lequel.

Les limites qu'il faut connaître

La fenêtre de contexte. C'est la vraie contrainte. Un export de 40 000 URLs ne rentre pas dans une conversation, et le modèle s'étouffe bien avant. D'où la règle : passer par des fichiers, laisser Claude écrire un script pour les traiter, et ouvrir une conversation neuve par tâche plutôt que d'empiler les sujets dans la même.

La sécurité. Autoriser un modèle à exécuter des scripts et à écrire des fichiers n'est pas anodin. Screaming Frog cantonne l'accès à un dossier que vous désignez, mais la règle de prudence reste la même que pour n'importe quel agent : un dossier dédié, et un œil sur ce qui s'exécute. C'est le même arbitrage que pour n'importe quel usage sérieux de Claude : ce qu'on gagne en autonomie, on le paie en vigilance.

Ce que ça ne remplace pas. Screaming Frog le dit lui-même dans sa documentation, et je le répète volontiers : l'IA améliore l'efficacité des tâches, elle ne remplace pas l'analyse. Trier 200 problèmes par « priorité » selon un barème générique n'a rien à voir avec décider ce qui compte pour ce site, ce business, ce trimestre. La méthode d'un audit SEO sérieux ne change pas ; seul le temps passé à fabriquer les tableaux diminue.

Et la Search Console dans tout ça ?

C'est la question qui termine la vidéo, et c'est là que l'installation devient vraiment rentable. Si vous connectez les API dans Screaming Frog — Search Console, Analytics, PageSpeed, Ahrefs — avant de lancer le crawl, leurs colonnes font partie du crawl. Claude les lit comme les autres.

Vous pouvez alors demander des croisements qui prennent d'habitude une demi-journée de tableur : les pages qui perdent des clics et qui ont peu de liens internes, les URLs en erreur qui recevaient encore du trafic le mois dernier, les pages lentes parmi celles qui rapportent le plus. C'est exactement le genre de tâche que je délègue, et c'est ce qui transforme un crawl en plan d'action.

Si ce type de branchement vous intéresse au-delà de Screaming Frog, c'est tout le sujet de l'automatisation IA sur vos propres outils : la même prise existe pour votre CRM, votre CMS ou vos exports comptables.

Questions fréquentes

Comment configurer le serveur MCP de Screaming Frog ?

Trois réglages suffisent. Dans Screaming Frog, « File > Settings > Storage Mode » doit être sur le stockage en base de données. Dans « File > Settings > MCP Server », il faut accepter l'environnement Node.js. Dans Claude Desktop, il faut installer l'extension spider-mcp.mcpb téléchargée depuis le guide utilisateur, via « Settings > Extensions > Advanced Settings > Install Extension », puis quitter complètement Claude et le rouvrir.

Le MCP fonctionne-t-il avec la version gratuite de Screaming Frog ?

Non. Le serveur MCP est réservé aux licences payantes, en version 24 ou supérieure. La version gratuite, limitée à 500 URLs, n'expose pas le serveur : le réglage n'apparaît pas dans les paramètres.

Comment utiliser Screaming Frog avec Claude ?

Une fois l'extension installée, vous parlez à Claude normalement. « Crawle exemple.fr et résume les problèmes par priorité » suffit à déclencher un crawl. Claude peut aussi lister les crawls récents, en charger un par son identifiant, sortir un export ou un rapport, écrire le résultat dans un fichier et générer un script Node.js pour retraiter ce fichier.

Pourquoi Claude ne trouve-t-il pas mon crawl ?

Parce qu'il est encore chargé dans l'interface. Tant que le crawl occupe l'écran de Screaming Frog, il n'est pas rangé dans la base de données et n'apparaît pas dans la liste des crawls récents. Videz-le une fois terminé, puis redemandez à Claude de lister les crawls : il le voit immédiatement.

STDIO ou Streamable HTTP : quelle différence ?

En mode STDIO, Claude lance lui-même Screaming Frog en ligne de commande : l'interface reste invisible, rien à démarrer à la main. En mode Streamable HTTP, vous ouvrez Screaming Frog normalement et vous démarrez le serveur MCP depuis le menu : vous voyez à l'écran ce que Claude manipule. STDIO pour l'automatisation, Streamable pour garder l'œil sur les données.

Quels outils sont compatibles avec le protocole MCP ?

Screaming Frog documente deux clients : Claude Desktop et LM Studio. LM Studio permet de travailler avec un modèle local, gratuit, à condition qu'il sache appeler des outils et que la machine suive. Tout client compatible MCP peut s'y connecter, mais ces deux-là sont les seuls avec une procédure officielle.

Comment exporter les données de crawl avec le MCP ?

En le demandant, en précisant l'onglet, le filtre, les champs et le nom du fichier. « Exporte les URLs HTML de l'onglet Internal dans internal.csv, uniquement les champs Address et Status Code » produit le fichier dans le dossier autorisé du serveur. Passer par un fichier plutôt que par la conversation évite de saturer la fenêtre de contexte.

Peut-on croiser les données Search Console dans un crawl piloté par Claude ?

Oui, à condition de connecter les API dans Screaming Frog avant de lancer le crawl. Les colonnes Search Console, Analytics, PageSpeed ou Ahrefs font alors partie du crawl, et Claude les lit comme les autres. C'est ce qui permet de prioriser les corrections par les clics réellement perdus.
